# Drafting support

Use this procedure when the user requests more guidance or selecting useful
instructions is uncertain. Work on the disputed entries; a clear existing rule
does not need a new analysis exercise.

## Decide what earns space

For each candidate, identify its source, affected work, and the mistake or
repeated discovery it prevents. Use governing instructions, approved user
choices, or maintained project evidence. An observed pattern can be evidence
about current practice without establishing a mandatory convention.

| Candidate | Treatment |
| --- | --- |
| Consequential project rule or exception | Keep with its applicability condition. |
| Detail already maintained elsewhere | Add a conditional pointer if discovery needs help. |
| Multi-step procedure needed for one task | Keep it in its owning document or skill. |
| Generic encouragement or easily discovered fact | Omit when it adds no distinct obligation. |
| Unconfirmed policy choice | Omit the addition, or ask if the decision is essential. |

Existing obligations remain authoritative until the requested change and its
evidence justify revising them. A recurring failure can justify making a rule
more explicit; model capability by itself is not permission to remove policy.

## Make the instruction usable

These examples assume the stated project facts are established; their paths
and rules are illustrative, not defaults to copy.

- Fact: published catalog records are referenced by stable identifiers.
  Instruction: "When revising a published record, preserve its identifier so
  existing references keep resolving."
- Fact: caption attribution requirements live in `docs/credits.md`.
  Instruction: "When changing caption attribution, read `docs/credits.md`."

Give a condition and concrete action instead of emphasis such as IMPORTANT.
Keep the reason only where it explains the choice. Add an example or acceptance
signal when wording alone leaves a real ambiguity, not to pad every rule.

For a new or disputed instruction, walk through one task that should trigger it
and one unrelated task. Narrow a rule that burdens the unrelated task. Check
the actual reference path and any stated command context. This walkthrough is
static review, not evidence of model behavior or successful command execution.

Stop when each disputed entry is retained, relocated, removed, or explicitly
unresolved. Return only the requested artifact or review, not the working table
unless requested. Revisit extra scaffolding after representative runs show
whether it helps; no improvement for a smaller model is established by this
guide's existence.
