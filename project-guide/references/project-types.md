# Project types

Select by the requested scope's purpose, deliverables, and maintenance workflow.
File extensions and isolated tools are supporting evidence, not a classification.

| Type guide | Read when |
| --- | --- |
| [Software](project-types/software.md) | The scope develops or maintains an application, library, service, or other executable product. |

If no guide matches, use the common assessment and uncertainty path in
`project-guide`. Missing coverage is not evidence that software rules apply.

## Extend the catalog

During requested skill maintenance, add one guide for a demonstrated project
type and link it here with a distinct selection condition. Each guide should
state the evidence that selects it, the contribution and management decisions
it informs, its authoritative sources, and meaningful validation. Keep shared
assessment in `project-guide` and AGENTS.md writing mechanics in `agents-writer`.

Add only conventions justified by the new type's actual needs. Where cases
overlap, specify which scope each guide governs. Recheck routing, references,
and a representative request for the new type; a consuming-project run may
report a coverage gap without modifying the installed skills.
